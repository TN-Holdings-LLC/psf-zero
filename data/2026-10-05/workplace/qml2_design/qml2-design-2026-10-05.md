# 量子 AI の次の段階の設計：QML-2「DEPTH」（職場、2026-10-05、案）

- **位置づけ：** 設計案。事前登録の文書ではない。段階 1 の予測は、職場のパイロット（第5節）を見たうえで、本番の前に事前登録で確定する。
- **前提：** 実機はまだ使えない。fake 機と Aer の雑音シミュレーションで進める。

## 1. 何を確かめるか

これまでの量子 AI の試験で分かったこと：

- 自宅の Addenda 291・297、職場の `qml-results-2026-10-05.md`。
- 4 量子ビット・浅い回路の分類器では、コンパイラの違いは「余裕（margin）」に出るが、「正答率」には出ない。
- 正答率が動いたのは、境目ぎりぎりの入力だけ（297 の fragile set）。

**つまり、規模を上げないと「賢さ」の差は見えない。** 次の問いは次の 3 つ。

| | 問い |
|---|---|
| Q-A | 雑音のある機械では、分類器を深くすると、どこかで正答率が頭打ちになり、下がり始めるか（雑音で決まる最適な深さ L\*）。 |
| Q-B | 良いコンパイラは、その山を高くするか、奥（深い側）へずらすか。量子ビット数を増やすと、コンパイラの差は広がるか。 |
| Q-C | 雑音を込みで学習させると、雑音なしで学習して配備するより山が上がるか（AI が雑音に合わせて賢くなるか）。 |

教師生徒の合成データだけでなく、**実データ**（scikit-learn に同梱され、ダウンロード不要）で確かめる。

## 2. 段階

**段階 1（CPU のみ。職場サンドボックスか自宅 PC。GPU は不要）**

- **データ：** breast_cancer（569 件、PCA で n 次元）、digits の 2 クラス（例：3 対 8、PCA）、教師生徒 1 種。
- **規模：** n = 4・6 は輪（CZ ring。ルーティングが必要で、コンパイラの差が出やすい）。n = 8 は鎖（触る量子ビットを 10 以下に抑えるため）。深さ L = 1, 2, 3, 4, 6, 8。
- **配備：** 雑音なしで学習した分類器を、各コンパイラで配備する。密度行列で計算し、読み出し誤りとショット 4,000 回を含める。
- **雑音込み学習：** L\* 付近だけで行う（SPSA、FakeAuckland、データ 1 種）。

**判定の関門：** 段階 1 で次の 2 つが両方見えたときだけ、段階 2 に進む。見えなければ段階 2 は不要で、GPU の費用はかからない。

1. 正答率が深さに対して山を持つ。
2. コンパイラ間で、山の高さか位置が、テスト点 1 つ分より大きく違う。

**段階 2（GPU）**

- n = 8 の輪、10、12（触る量子ビットは 15 以下）。Aer の GPU 版で密度行列を計算する。
- 余力があれば、16〜24 量子ビットを軌跡法（状態ベクトルに雑音を確率的に入れる方法）で、配備のみ行う。

## 3. 方式と機種

| 方式 | 内容 |
|---|---|
| C12 | 採用されればリリース。採用されなければ R41（10-04.1 の推奨呼び出し） |
| RPSF | 10-02.2 の呼び出し（guard だけ） |
| L3T | Qiskit level 3 に Target を渡したもの |
| A9 | AI 前段（8 量子ビット以下） |
| IDEAL | 雑音なし（上限の目安） |

**機種：** FakeAuckland（cx）、FakeTorino と FakeKingston（cz）。A0（Addendum 293）で下限の問題が最も多かった ecr 機は、パイロットでリリースが正しくコンパイルできることを確かめたうえで、報告のみで 1 台加える案。

## 4. 指標と予測の骨組み（数値はパイロット後に確定）

**指標：**

- 正答率（ショットと読み出し誤りあり）
- 余裕
- L\* と山の高さ
- 学習曲線
- コストの内訳：コンパイル時間と、回路の実行回数（実機に置き換えたときの QPU 時間の目安）

**予測の案：**

| ID | 予測 |
|---|---|
| P1 | n ≥ 6 の cx 機で、雑音下の正答率は深さに対して山を持つ（L\* < 8） |
| P2 | 山の高さは C12 ≥ RPSF。L\*(C12) ≥ L\*(RPSF) |
| P3 | 山の高さで C12 と L3T の差はテスト点 1 つ以内 |
| P4 | L\* では、雑音込み学習が配備のみの正答率を上回る |
| P5 | n を上げるほど、C12 と RPSF の差は広がる |

**正直に書いておくこと：** A9 と C12 の見積もりは、シミュレーターと同じ物理の仮定に立っている。シミュレーションでは有利に出るので、実機での確認が別に必要（これまでと同じ注意）。

## 5. 職場のパイロット（開発用データのみ。試験ではない）

結果と、設計への反映は、引き継ぎ書の第3節を参照（FakeTorino は職場で続行中）。要点は 3 つ。

- n = 6・cx 機では、余裕は L = 2〜4 で山を持つが、正答率は L = 8 まで上がり続けた。
- このため、深さを 16 まで延ばし、ショット・読み出し誤り・境目の入力の組を入れる。
- n = 8 以上は GPU の段階に回す。

## 6. 計算量（職場サンドボックスで測った値、CPU 2 個）

ring 型モデルを、10-04.1 の推奨呼び出しでコンパイルし、Aer の密度行列（雑音あり）で 1 回路を計算した時間。

| 触る量子ビット | 1 回路の密度行列計算 | コンパイル |
|---|---|---|
| 6 | 0.5〜5 秒 | 0.3〜0.5 秒 |
| 12 | 7〜18 秒 | 0.3〜0.8 秒 |
| 14 | 140〜280 秒 | 1〜2 秒 |

**大事な点：** 計算の重さは、論理的な量子ビット数ではなく、ルーティング後に「触る」量子ビット数で決まる。たとえば n = 8 の輪は、12 個の量子ビットを触った。

**見積もり：**

- **段階 1（n = 4・6 の輪と、n = 8 の鎖）：** 配備がおよそ 4 万回路で、職場サンドボックスなら 3〜5 時間、自宅 PC（6 並列）なら 1〜2 時間。雑音込み学習（データ 1 種、2 シード）は自宅で数時間。
- **段階 2（触る量子ビット 12〜15）：** CPU では 1 機種・1 条件あたり数十時間かかり、現実的でない。GPU なら、1 回路あたり 12 量子ビットで 0.2〜0.5 秒、14 量子ビットで数秒と見込む（未測定。パイロットで確かめる）。
  - 配備はおよそ 4 万回路で、**GPU 6〜25 時間ほど**。料金は、その日の時間単価を掛けて見積もる。

## 7. GPU を手配する場合の仕様（段階 2 に進むときだけ）

**機材：**

| 項目 | 仕様 | 理由 |
|---|---|---|
| GPU | RTX 4090（24 GB）1 台で足りる | 密度行列は 15 量子ビットで約 17 GB。16 量子ビット（約 69 GB）が必要になったときだけ、A100/H100（80 GB）にする |
| vCPU | 16 以上 | コンパイルは CPU で並列に行うため |
| RAM | 32 GB 以上 | |
| ディスク | 30 GB | |

**ソフトウェア：**

- Python 3.11 か 3.12、Qiskit 2.5.2、qiskit-ibm-runtime 0.49.0（fake 機）、Rust コア 2026-09-29.1（ビルドするか、ホイールを持ち込む）。
- **Aer の GPU 版の注意（PyPI で確認済み）：**
  - CUDA 12 向けの `qiskit-aer-gpu` は、PyPI では 0.15.1 が最新。
  - これまでの試験と同じ 0.17.2 は、`qiskit-aer-gpu-cu11`（CUDA 11 ランタイム向け）しかない。
  - **推奨は、`qiskit-aer` を外して `qiskit-aer-gpu-cu11==0.17.2` を入れ、CUDA 11 のランタイムを pip で入れる方法。** CUDA 12 のドライバーは CUDA 11 のランタイムを動かせる。
  - **最初に必ず確かめること：** パイロットの回路で、GPU の結果が CPU（0.17.2）と 1e-10 以内で一致すること。
- **Pod の作成と支払いは、ご本人の合図があってから**（引き継ぎ書第8節）。

**GPU での手順案：**

1. 1 時間ほどのパイロット：環境の確認、CPU との一致、1 回路あたりの時間を測る。
2. その実測で段階 2 の規模を確定し、事前登録する。
3. 本番。

2. GPU は、段階 1 の関門の判定後でよいか（判定まで GPU の費用はかからない）。
