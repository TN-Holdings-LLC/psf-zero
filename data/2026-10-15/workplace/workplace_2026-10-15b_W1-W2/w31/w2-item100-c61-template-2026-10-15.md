## 1. Item 100 (`make_c61.py`, exact substitutions on c60)

**The API**, after a20's `RingTemplate`:

- `compile_template(qc, target, seed_transpiler=0)` returns a `CompileTemplate` with `.values_of(qc)`,
  `.bind_values(values)`, `.bind(qc)`, `.signature` and `.circuit`.
- It follows c60's path: item 96's scope, then item 87's chain, item 91's graph, item 99's native gates.
  `OutOfScopeError` where c60 refuses.
- c60's default call is unchanged. Items 87 and 91 gain a hook, unset by default, that hands their structure to the
  template before their Qiskit stage.

**What a template does.**

- It is built once. Each bind is closed form only: single-qubit runs by ZYZ, two-qubit forms as at build, then
  assign_parameters. No pass manager, no simulation.
- **Item 99 inputs:** the same steps as c60, split into structure (placement, order, fixed gates' native forms) and
  values (every gate parameter, in the input's order). The output is c60's, value for value.
- **Items 87/91, frame path (F):** the same logical circuit, the same RemoveDiagonalGatesBeforeMeasure positions
  (applied by rule and checked against Qiskit's pass at build) and the same Pauli X frame. Runs are merged by PSF-Zero
  instead of Qiskit's Optimize1qGatesDecomposition.
- **Items 87/91, CZ path (T):** c60 ends with Qiskit's level 3, which a template may not run. PSF-Zero emits it:
  - every two-qubit term is a local Clifford around RZZ;
  - consecutive terms on one pair form one block (single-qubit operations between them are absorbed);
  - a block of exactly XX + YY + ZZ uses a closed-form 3-CNOT circuit of exp(i(aXX + bYY + cZZ)), found by search
    and checked for 300 random (a, b, c) in [-10, 10];
  - other blocks use Qiskit's Weyl decomposition with closed-form circuits;
  - diagonal terms directly before the measurements are left out;
  - a run with theta = pi is one x pulse.

**The shape signature.**

- It is the input's structure plus the output's gate sequence. When values change it, the new shape's circuit is built
  ("rebuilt") or taken from a cache of up to 256 shapes ("switched").
- **Value-dependent branches found:**
  - item 99: each run's class (none / z / half / full); the RZZ class (0; pi/2 as cz; otherwise rzz or cz rz cz); a
    block's CZ count (Weyl single interaction / c = 0 / generic);
  - item 88's frame: a zero angle drops the rzz; a sign change inserts an x, which can create a run where there was
    none. Folding by pi only adds rz(pi), which is merged.
  - CZ path: the x-pulse class (theta = pi), and the Weyl chamber's local gates;
  - a coefficient of 0: an rzz or block disappears (shape changes; caught);
  - item 99's diagonal class is decided by gate name for gates with a parameter, so it never depends on a value;
  - RemoveDiagonalGatesBeforeMeasure is structural (gate names).

**Tests.** `test_c61.py`, 8 passed:

- the canonical closed form (300 random draws);
- native templates identical to c60 at the build and at random values;
- frame and CZ-path templates exact;
- a rebuild on a sign change, still exact;
- structure mismatch and out-of-scope refusals;
- c61's default call identical to c60.

**Rebuilds.**

- Same-sign draws keep the shape in every test but one: hhtree_heis T changed shape on 995 of 1000 (the Weyl
  chamber's local gates vary with the values).
- The free draws (random signs) changed shape on 73-100 of 100 on the frame path, through item 88's frame.
- In the 100k loop (random walk with steps of N(0, 0.05) on every value):
  - T: 127 new shapes and 16,334 cache switches;
  - **F: 64,766 new shapes in 100,000 binds.** Small angles wander across zero and item 88's frame changes shape.
    Median bind 2.5 ms, p99 7.5 ms, one bind at 2.0 s (likely garbage collection).

**Memory note** (it does not change T7's verdict by its pre-registered measure, but home should know). In the F loop,
peak RSS rose from 307 MB to 1,142 MB within the first 10,000 laps, then stayed flat. That is the 256-shape cache
filling with 20-qubit circuits. It is bounded, but large. A smaller cache, or a frame shape that does not depend on
signs, would fix it.

## 3. Reading and proposals

- **The template is safe.** It was correct in every one of 49,590 outputs, across 5 devices and every rebuild. On
  item 99 inputs it is c60 value for value.
- **Speed is not yet at target.** It meets 2 ms in 25 of 38 cells. Where it misses, it is still 10-30 x faster than
  c60's compile (30-90 ms), but slower than Qiskit's plain assign_parameters.
- **The CZ path of items 87/91.** The template's own emission is shorter than c60's on Ising chains, lattices and rings
  (0.76-0.83). Proposal for home, not built into c60/c61: emit items 87/91's CZ path this way in the default call
  too, i.e. drop the level-3 stage. For Heisenberg-type blocks, decide between the fast closed form and the Weyl form
  before that; the Weyl form matched Qiskit at build values.
- **Item 88 in a training loop.** With angles near zero, the frame's shape changes on most binds. A sign-independent
  emission costs pulses against c60, so a choice is needed. It is reported here, not decided.
