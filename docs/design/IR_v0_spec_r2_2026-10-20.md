## 1. Schema changes (draft 2020-12)

The top level is now one of two records:

The full schema is `psf-intent-0.r2.schema.json` next to this file; the changes in short:

```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "$id": "psf-intent/0",
  "title": "psf-intent IR v0 (r2)",
  "oneOf": [{"$ref": "#/$defs/intent"}, {"$ref": "#/$defs/decline"}],
  "$defs": {
    "decline": {
      "type": "object", "additionalProperties": false,
      "required": ["ir", "decline"],
      "properties": {
        "ir": {"const": "psf-intent/0"},
        "decline": {"enum": ["out_of_family"]}
      }
    },
    "intent": {
      "type": "object", "additionalProperties": false,
      "required": ["ir", "family", "params", "output", "device"],
      "properties": {
        "ir": {"const": "psf-intent/0"},
        "family": {"enum": ["tfim_chain", "ring_classifier", "rzz_layer"]},
        "output": {"enum": ["template", "circuit"]},
        "device": {"type": "string",
                   "pattern": "^file:[A-Za-z0-9._-][A-Za-z0-9._/-]{0,254}$",
                   "not": {"pattern": "\\.\\."}},
        "device_sha256": {"type": "string", "pattern": "^[0-9a-f]{64}$"},
        "twin": {"type": "object", "additionalProperties": false,
                 "required": ["requested"], "properties": {"requested": {"type": "boolean"}}},
        "params": {"type": "object"}
      },
      "oneOf": ["... the three family branches of the draft, unchanged ..."]
    },
    "ring_classifier": "... as the draft, except n:",
    "ring_classifier.n": {"type": "integer", "minimum": 2, "maximum": 64}
  }
}
```

- **The decline record** builds nothing, reads no device file, and is not a refusal. Gate 1 returns
  `{"declined": true, "reason": "out_of_family"}`. The model emits it for a request outside the three families.
- **The device path** is relative, from the gate's configured device directory: no leading `/`, no `..`, no `:`
  after `file:` (so no URL). Absolute paths and URLs fail the schema.
- **`twin.requested`**: when true, check T3 applies (TFIM). For other families gate 1 has no twin check; the twin
  applies its own bound when it runs (`TWIN_BOND_LIMIT` at the twin step).
- **`ring_classifier.n`**: the schema keeps only the type and the absolute caps (2 to 64). Evenness and n ≥ 12 are
  checked by R2, so the codes `RING_ODD` and `RING_TOO_SHORT` are reachable for this family.

## 2. Gate 1: the order of checks (r2)

| # | check | pass when | refusal code |
|---|---|---|---|
| 0 | parse | the text is JSON. Numbers are parsed as f64; a literal that overflows (1e999) becomes ±inf here and is caught by check 2. NaN and Infinity are not JSON and fail here | `SCHEMA_INVALID` |
| 1 | version | the top level is an object whose `ir` is a string equal to "psf-intent/0". Missing or not a string: `SCHEMA_INVALID`; another string: `IR_VERSION` | `IR_VERSION` |
| 2 | finite numbers | every number in the record is finite | `NUMBER_NOT_FINITE` |
| 3 | schema | the record validates against §1 | `SCHEMA_INVALID` (field path in the reason) |
| D | decline | the record is a decline record: return `declined`, stop | (not a refusal) |
| 4 | device file | was check 3 of the draft, unchanged | `DEVICE_UNREADABLE`, `DEVICE_HASH_MISMATCH` |
| 5 | device gate set | was check 4 of the draft, unchanged | `TEMPLATE_ECR_UNSUPPORTED` |
| R1-R5, T1-T3, Z1-Z6 | as the draft | as the draft; R2 is now reachable; T3 only when `twin.requested` is true | as the draft |
| 9 | psfz build | as the draft | `BUILD_REFUSED` |

- **Z2 and Z5 apply only when `angles` is an array.** When it is "slots", Z2 and Z5 are skipped and Z6 refuses.
- **19 refusal codes,** the draft's list unchanged (the "20" in instruction 5 was a miscount).

## 3. The rzz natives in the device file (needed by Z4 and Z5)

The draft leaves the device side open. r2 names the fields gate 1 reads, so that N2's synthetic fixture F4 can be
written; the values stay the device's:

```json
"rzz_native": {"couplers": [[a, b], ...], "angle_min_exclusive": 0.0, "angle_max": 0.5}
```

- Z4 passes when `rzz_native` is present and lists every coupler of the placement.
- Z5 folds each angle by the draft's identities into [0, π/2]: t = θ mod π in [0, π), folded = min(t, π − t). It
  passes when angle_min_exclusive < folded ≤ angle_max.
- No real device file has this field yet. psfz ignores unknown fields, so it changes nothing else.

## 4. What stays open (unchanged from the draft)

- The numeric limits CZ_max, SX_max, χ_max (`[ ]`). N2 uses test values, labelled as such.
- Whether `circuit` output for TFIM is in v0 (draft §5). N2's control K4 assumes it is.
- TFIM's second-order splitting k and the rzz angle convention (T2).
- Whether T3 moves after the build as one function on the built artifact (W2 §6.1). N2's R14 and K5 give the same
  answer either way for a TFIM chain without crosstalk, where the two formulas agree exactly.
